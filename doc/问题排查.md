# 问题排查：自定义开奖后历史页面仍显示未开奖

排查时间：2026-07-02

## 现象

客户反馈：后台自定义开奖后，历史下单里已经能看到开奖/结算结果，但控盘管理的历史记录页面仍显示：

- 实际开出：未开奖
- 实际利润：-
- 状态：未开奖

截图中的表头为“实际开出 / 实际利润 / 状态 / 操作”，对应的是 admin 前端 `control-panel/history` 页面，不是“历史下单”页面。

## 当前结论

按业务规则理解，前端应该等到开奖时间到达后才允许开奖。封盘后到开奖前这段时间，只应该显示“距离开奖”或“等待开奖中”，不应该提前把本期开奖结果写出来。

但当前代码里，“自定义开奖”并没有等到开奖时间。按照当前后端代码，点击“自定义开奖”并确认后，接口会立即：

1. 写入 `la_lottery_issue.result`
2. 将 `la_lottery_issue.status` 更新为 `3`
3. 调用下注结算逻辑更新 `la_betting_record`
4. 将 `la_lottery_issue.is_settled` 更新为 `1`

所以这次问题实际有两层：

1. 时间控制问题：当前 admin 自定义开奖在封盘后就能开奖，没有强制等到开奖时间。
2. 展示同步问题：开奖后 `la_best_plan_history` 没有同步更新，所以控盘历史记录仍显示“未开奖”。

“历史下单已经有开奖”是合理的，因为历史下单读的是 `la_betting_record`。截图仍显示“未开奖”的直接原因是：`la_best_plan_history` 没有被同步更新。

## 代码链路

### 前端时间控制链路

admin 实时分析页面：

```text
vue/admin/apps/web-antd/src/views/control-panel/analysis/index.vue
```

当前倒计时展示逻辑是正确区分了三个阶段：

```text
未开盘 -> 距离开盘
开盘中 -> 距离封盘
已封盘但未到开奖时间 -> 距离开奖
开奖时间已过但未开奖 -> 等待开奖中...
```

对应代码里使用了：

```text
openTime = qishuInfo.opentime
closeTime = qishuInfo.closetime
drawTime = qishuInfo.kjtime
```

但是“自定义开奖”按钮当前只判断了 `isBeforeCloseTime()`：

```text
Date.now() < closetime -> 禁止自定义开奖
Date.now() >= closetime -> 允许自定义开奖
```

也就是说，当前 admin 前端在“封盘后、开奖前”这段时间已经可以点自定义开奖，这和“必须到开奖时间才开奖”的业务要求不一致。

home 用户端倒计时逻辑也按开奖时间展示：

```text
vue/home/src/components/Layout/Header.vue
已封盘时使用 seconds_to_kj / seconds_to_draw 显示“距离开奖”
开奖时间过后仍未开奖时显示“等待开奖中”
```

所以用户端展示逻辑倾向于“到开奖时间后才开奖”，问题主要出在 admin 自定义开奖入口和后端接口没有强制校验 `draw_time`。

### 自定义开奖链路

入口：

```text
server/app/adminapi/controller/BestPlanController.php
customDrawing()
```

实际逻辑：

```text
server/app/api/logic/BestPlanLogic.php
customDrawing()
```

当前 `customDrawing()` 只校验了封盘时间：

```text
time() < close_time -> 当前期号尚未封盘，不能自定义开奖
time() >= close_time -> 允许继续开奖
```

它没有校验：

```text
time() < draw_time -> 未到开奖时间，不能开奖
```

所以只要过了封盘时间，即使还没到开奖时间，后端也允许自定义开奖。

接口继续执行后会更新：

- `la_lottery_issue.result`
- `la_lottery_issue.planned_result`
- `la_lottery_issue.status = 3`
- `la_lottery_issue.is_settled = 1`
- `la_betting_record` 中奖/未中奖状态

但没有更新：

- `la_best_plan_history.status`
- `la_best_plan_history.actual_number`
- `la_best_plan_history.actual_profit`

## 另一个文案/语义问题

实时分析页面有两个动作需要区分：

### 自定义开奖

业务期望应该是“到开奖时间后才允许开奖”。

当前代码实际是“封盘后即可立即开奖并结算”，不是等到开奖时间。

### 用此方案开奖

当前 `executeDrawing()` 从代码看只是把号码写入 `la_lottery_issue.planned_result`，也就是保存人工计划号，并没有立即写入 `result`，也没有立即结算下注。

但前端按钮和提示文案写的是“用此方案开奖 / 开奖成功”，这会误导客户以为已经完成开奖。

这里后续需要做产品确认：

1. 如果这个按钮应该只是提前设置计划号，前端文案应改成“保存人工计划号”。
2. 如果这个按钮应该立即开奖，则后端 `executeDrawing()` 要改成和 `customDrawing()` 一样写 `result`、结算订单、同步历史表。

## 临时修复 SQL

如果只是要先修复线上已有历史记录显示，可以执行下面 SQL。

注意：执行前建议先备份或先 SELECT 核对影响行。

### 先核对异常记录

```sql
SELECT
  h.id,
  h.gid,
  h.qishu,
  h.plate_code,
  h.status AS history_status,
  h.actual_number,
  h.actual_profit,
  i.id AS issue_id,
  i.status AS issue_status,
  i.result,
  i.is_settled
FROM la_best_plan_history h
JOIN la_lottery_issue i
  ON i.game_id = h.gid
 AND i.issue = h.qishu
 AND i.plate_code = h.plate_code
WHERE i.status = 3
  AND i.result IS NOT NULL
  AND i.result <> ''
  AND i.is_settled = 1
  AND h.status = 0;
```

### 同步已开奖的方案历史

`actual_number` 当前字段只能存一个号码，所以按现有表结构同步为特码，也就是开奖结果最后一个号码。

`actual_profit` 建议按实际下注结算计算：总下注金额 - 总派彩金额。

```sql
UPDATE la_best_plan_history h
JOIN la_lottery_issue i
  ON i.game_id = h.gid
 AND i.issue = h.qishu
 AND i.plate_code = h.plate_code
LEFT JOIN (
  SELECT
    game_id,
    issue,
    plate_code,
    SUM(total_amount) AS total_amount,
    SUM(prize_amount) AS prize_amount
  FROM la_betting_record
  GROUP BY game_id, issue, plate_code
) b
  ON b.game_id = h.gid
 AND b.issue = h.qishu
 AND b.plate_code = h.plate_code
SET
  h.status = 1,
  h.actual_number = CAST(SUBSTRING_INDEX(i.result, ',', -1) AS UNSIGNED),
  h.actual_profit = ROUND(COALESCE(b.total_amount, 0) - COALESCE(b.prize_amount, 0), 2)
WHERE i.status = 3
  AND i.result IS NOT NULL
  AND i.result <> ''
  AND i.is_settled = 1
  AND h.status = 0;
```

## 建议的代码修复路径

### P0：自定义开奖必须等到开奖时间

需要同时改前端和后端，不能只靠前端禁用按钮。

前端：

- 新增 `isBeforeDrawTime()`，按 `qishuInfo.kjtime` 判断是否未到开奖时间。
- 自定义开奖按钮禁用条件从“未封盘禁止”改成“未到开奖时间禁止”。
- 点击时如果未到开奖时间，提示“当前期号尚未到开奖时间，不能开奖”。

后端：

- `customDrawing()` 增加 `draw_time` 校验。
- 如果 `time() < draw_time`，直接返回“当前期号尚未到开奖时间，不能开奖”。

这样即使有人绕过前端直接请求接口，也不能提前开奖。

### P1：补齐自定义开奖后的历史同步

在 `customDrawing()` 确认到开奖时间并结算成功后，同步更新 `la_best_plan_history`：

- `status = 1`
- `actual_number = 开奖结果最后一个号码`
- `actual_profit = la_betting_record 总下注 - 总派彩`

这样可以保证客户点击“自定义开奖”后，历史下单和方案历史显示一致。

### P2：自动开奖命令也同步历史表

`php think draw:lottery` 自动开奖结算后，目前也只更新期号和下注记录，没有看到它同步 `la_best_plan_history`。

建议在自动开奖结算成功后调用同一段同步逻辑，避免自动开奖后历史页面也显示未开奖。

### P3：修正“用此方案开奖”的产品语义

当前按钮名称和后端行为不一致。

建议二选一：

1. 保持后端只保存计划号，前端按钮改为“保存人工计划号”，成功提示改为“人工计划号已保存，开奖时间到后由定时任务发布并结算”。
2. 改成真正立即开奖，后端写入 `result`、结算下注、同步 `la_best_plan_history`，前端继续叫“用此方案开奖”。

### P4：历史页面展示来源优化

为了减少表不同步导致的误解，历史记录接口可以在返回 `la_best_plan_history` 时关联 `la_lottery_issue`：

- 如果 `la_lottery_issue.status = 3` 且 `result` 不为空，但 `la_best_plan_history.status = 0`，接口可以即时补全或至少返回真实开奖状态。
- 长期更推荐在开奖结算事务里同步写表，接口只负责展示。

## 给客户的解释口径

按业务规则，自定义开奖应该等到开奖时间后才允许执行；封盘后到开奖前只能等待开奖，不能提前开奖。

当前线上出现的问题有两层：

- admin 自定义开奖入口当前只限制到封盘时间，过了封盘就能开奖，没有强制等到开奖时间。
- 页面不一致不是下注没有结算，而是后台有两个展示来源：

- 历史下单读取下注表，所以已经显示开奖结果。
- 控盘历史记录读取方案历史表，而这张表没有在开奖后同步，所以仍显示未开奖。

后续修复方向是：先限制必须到开奖时间才能开奖，再在开奖成功后同步方案历史表，保证两个页面状态一致。
